# Project documentation

Start with the product brief, then use the MVP and integration docs to guide implementation. Team coordination guidance is separate from product and technical architecture.

- [Product vision](product/vision.md) — user, problem, product thesis, and long-term differentiation.
- [MVP and demo plan](product/mvp.md) — hackathon scope, user flow, success criteria, and explicit stretch goals.
- [Integration architecture](architecture/README.md) — data boundaries, contracts, provenance, and staged cross-layer composition.
- [Development workflow](development/workflow.md) — ownership, coordination, and repository hygiene for parallel work.

The product vision is intentionally broader than the hackathon MVP. Treat data availability and analytic claims as unvalidated until confirmed against sponsor documentation and real sample data.
